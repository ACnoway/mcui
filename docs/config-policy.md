# 配置语义与 Helper 固定操作策略

配置默认拒绝。首个可下发模板仅用于经独立清单审核的 Xray `v26.10.31`，并要求节点 root 提供本地策略。能力状态、制品审核和部署步骤分别见[兼容矩阵](./core-compatibility.md)、[制品信任](./artifact-trust.md)和[受控入站部署](./phase-4-xray-inbound.md)。

## 1. 拒绝优先及授权

仅允许已审核的 Core、精确版本、构建和节点策略组合。未知字段、重复 key、无效值和超限数据直接拒绝。主控与独立签发端约束模板版本、目标制品及配置引用。Agent 校验签名与节点，Helper 独立验签、复验制品清单与租约，在本地按模板生成并校验配置。签名、Core 语法检查和 UI 限制均不能替代语义校验。

Xray `config.apply` 绑定节点、精确版本与制品 SHA-256、清单版本、监听端口、修订号和渲染后的原始字节 SHA-256 与长度。签名配置元数据和签名任务一起校验。配置正文仅在节点 root 私有目录中生成，由 systemd 以服务凭据读入。预检在无外网的低权限 unit 中运行。[任务协议](./agent-protocol.md#4-任务配置和控制消息)

## 2. 允许范围的约束

| 类别 | 决议 |
|---|---|
| 业务监听 | 仅经节点策略批准的地址、协议、端口与入站类型；拒绝通配地址的管理监听；检查 TCP/UDP、IPv4/IPv6 及其他 Core 的实际冲突。低端口能力只按已审核模板授权。 |
| 管理/统计 API | 默认禁用；仅版本矩阵验证后允许固定本地端点及独立访问控制；不得公网监听，不能仅依赖回环地址当作认证。 |
| 文件/日志/凭据 | 不允许任意路径、文件 URI、脚本、命令、插件；引用只能是预定义的 Core 专属资源 ID，由本地安全映射并防链接逃逸；不得读取 Agent、Helper、其他 Core 凭据。日志仅固定目标并脱敏。 |
| 外部资源 | 默认禁用远程规则、订阅、证书及动态下载；以后仅经审核固定来源及内容摘要且经节点策略许可，无法约束即拒绝。 |
| 出站与路由 | 默认无通用自由出站；只允许经批准的类型、目标类别和策略组合；禁止访问本机管理端口、云元数据及受保护网段，须处理 DNS 重绑定和 IPv4/IPv6 变体；无法约束运行时解析时禁用该能力。 |
| 用户及秘密 | 仅许可已验证的用户/入站字段与授权关系；秘密最小权限传输和落盘，不写日志、审计或错误。 |

首个模板固定监听隔离网络命名空间中的 `127.0.0.1` 非特权端口，SOCKS5 密码认证只使用本地用户标识 `mcui`。固定规则仅允许字面公网 IPv4 和单一 TCP 端口，其余连接默认进入 `blackhole`。域名、UDP、IPv6、回环/私网/保留目的地址、任意配置字段和管理 API 均禁用。每个新增组合都须验证正反例。

## 3. Helper 操作清单

Helper 仅限受控 UDS、Socket 权限及 `SO_PEERCRED`，并独立验证任务签名、节点、时间、序号及 root 私有防重放账本；凭据检查不能替代签名。未知操作或多余字段直接拒绝，所有固定目录、unit、权限、命令参数均由 Helper 内部映射，不接受调用者提供路径、URL、unit、shell 或 argv。

| 固定操作 | 签名精确绑定及效果 |
|---|---|
| `STATUS` | 节点、任务、Core；仅读取内部映射的服务状态，不暴露秘密。阶段 2 首先且仅开放此项。 |
| `INSTALL_ARTIFACT` | 节点、任务、步骤、Core、版本、架构、制品 ID、清单版本及摘要；仅将复验的内容放入该 Core 不可变版本目录。 |
| `ACTIVATE_VERSION` | 同上及目标版本、期望当前版本/LKG；只切换固定 Core 的版本指针并记录事务。 |
| `WRITE_CONFIG` | 节点、任务、步骤、Core、版本、策略版本、revision、长度和摘要；只写固定 Core 配置目录并复验精确内容。 |
| `SERVICE_CONTROL` | 节点、任务、步骤、Core、动作枚举 start/stop/restart 和期望状态；仅控制该 Core 内部固定 unit。 |
| `RESTORE_LKG` | 节点、原事务、步骤、Core、已记录 LKG 版本与配置摘要；仅故障恢复事务允许，不接受任意旧路径。 |
| `UNINSTALL_CORE` | 节点、任务、步骤、Core、期望版本和保留策略；仅删除内部固定受控范围，默认保留必要备份及审计。 |

各步骤顺序、前置状态和精确实际参数必须与签名授权一致。账本先持久化意图，再持久化结果，重启先对账。失败保持 LKG 或明确 `ROLLBACK_FAILED`。自身更新使用独立授权和监督。

## 4. 配置切换及验收

申请前保存二进制、配置与服务状态 LKG；按 Core 适配事务切换并验证健康，失败恢复且复核。手动回滚生成新 revision；序号回退拒绝。mita 若内部持久化，须证明实际状态快照/恢复，不能仅切换外部文件；无法恢复则安全停机并告警。

扩展模板或发布前应复验以下边界：

| 输入/故障 | 预期 |
|---|---|
| 已签名配置加入未知字段、未授权监听、管理 API、越界路径或远程资源 | 主控和 Agent 各自拒绝，无特权副作用 |
| 跨 Core 配置、摘要/版本/节点/策略篡改、旧 revision | 拒绝，LKG 不变 |
| 合法任务中替换实际制品/步骤/action，添加 `sshd.service` 或路径 | Helper 拒绝；root 文件和其他服务不变 |
| 非 Agent 调用、重放、重启中断 | 拒绝或对账，不重复副作用 |
| 配置预检失败、端口冲突、磁盘满、回滚失败 | 不提交；可恢复则复核 LKG，否则显式失败和告警 |
