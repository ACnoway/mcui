## 4. 成为已验证的证据与测试

1. 记录具体版本、架构、发行版/内核/systemd、构建选项、目标制品摘要、来源及可复核的签名与审核证据；按架构分别记录测试日期、执行人、环境与日志。对没有上游签名的制品按内部审核流程标识，不冒称上游已签名。
2. 干净 VM 验证空 Agent、制品认证、错误架构/摘要拒绝、安装启停、健康检查、升级、需审批降级、卸载及断电/磁盘满恢复；同节点三 Core 隔离、端口冲突及跨 Core 更新影响分别验证。
3. 逐版本配置允许字段及默认值建立正反例，验证目标版本预检、策略拒绝、失败时 LKG 恢复及实际监听；预检在低权限沙箱。mita 必须测真实内部持久化位置、replace/重启、快照恢复；无法证明恢复则禁用该变更或安全停机。
4. 统计逐用户验证身份映射、上下行、重启/重置、采样、重复与缺口、计数窗口以及离线补报；无法可靠增量时标 `UNSUPPORTED` 并禁用精确额度。热重载须逐变更类型证明行为，不推断全量支持。
5. 每条能力记录通过/失败、测试命令及结果、报告位置和审阅人；任何版本、构建、平台或策略变化使相关结论回到待验证。漏洞或证据撤销时立即停止新安装并评估运行实例。
