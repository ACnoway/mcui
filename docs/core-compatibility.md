## 3. 能力矩阵

阶段 3 的面板版本目录读取官方 Releases 元数据，列出近期版本和下载资产；目录条目不改变本表的能力状态，也不构成产品支持、内部批准或安装授权。只有按本文件第 4 节完成逐版本、逐架构测试并登记证据后，才能将对应能力从“待验证”改为“已验证”。

`待验证`：没有可复核的特定组合证据；运行时表现为禁用并显示 `UNSUPPORTED`（原因：待验证），不等于已证明上游没有该功能。`已验证` 仅能由通过标准且有证据的组合获得；`不支持` 表示经调查确认不提供或产品明确不做。统计未知不得显示零用量，也不得启用精确额度。

## 4. 成为已验证的证据与测试

1. 记录具体版本、架构、发行版/内核/systemd、构建选项、目标制品摘要、来源及可复核的签名与审核证据。记录 amd64 运行测试与 arm64 构建的日期、环境和日志。对没有上游签名的制品按内部审核流程标识，不冒称上游已签名。
2. 在隔离的 Debian amd64 环境验证空 Agent、制品认证、错误架构和摘要拒绝、安装启停、健康检查、升级、显式降级和卸载。阶段 3 的恢复测试在候选版本提交前强制终止事务进程，重启后确认最后一次成功提交的版本恢复运行。三 Core 的同节点隔离、端口冲突和更新影响分别验证。
3. 逐版本配置允许字段及默认值建立正反例，验证目标版本预检、策略拒绝、失败时 LKG 恢复及实际监听；预检在低权限沙箱。mita 必须测真实内部持久化位置、replace/重启、快照恢复；无法证明恢复则禁用该变更或安全停机。
4. 统计逐用户验证身份映射、上下行、重启/重置、采样、重复与缺口、计数窗口以及离线补报；无法可靠增量时标 `UNSUPPORTED` 并禁用精确额度。热重载须逐变更类型证明行为，不推断全量支持。
5. 每条能力记录通过/失败、测试命令及结果、报告位置和审阅人；任何版本、构建、平台或策略变化使相关结论回到待验证。漏洞或证据撤销时立即停止新安装并评估运行实例。
