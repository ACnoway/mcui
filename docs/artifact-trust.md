# 制品信任方案（阶段 0 决议基线）

状态：已选择标准 **TUF** 作为发布元数据设计基线，**尚未实现、验签或验收**。适用于 Core、Agent 与 Helper；各自更新授权分离。该选择等待项目/安全负责人批准，阶段划分见 [工作流](./phased-development-workflow.md)，版本状态以 [能力矩阵](./core-compatibility.md) 为准。

## 1. 方案与角色

选择标准 **TUF** 客户端和仓库，而非自制简化清单。实现及规范版本、依赖锁定和互操作测试记录在实施前确定；不得声称已验证。离线根角色 2-of-3 独立保管人；targets 2-of-3 独立发布审核人；snapshot 和 timestamp 各 1-of-1 在线专用密钥，最小权限且彼此分离。根私钥不进入 Web、任务签发或节点；Core targets 与 Agent/Helper targets 使用独立委派角色和密钥，各 2-of-3，授权路径互不重叠。单人不得同时控制同一角色阈值。制品发布审核人与任务签发人职责分离；高危任务仍须单独审批，TUF 不替代任务签名。

通过已验证的线下渠道在安装包中引导可信 TUF root，核对公钥指纹，包本身也必须通过独立可信渠道校验；不得通过首次联网自动信任根。TUF 元数据按所选规范实现标准签名封装和规范化，任务/配置签名另遵循其协议，不能混用或自行改写 TUF 格式。

## 2. 入库与消费

发布审核固定上游项目、版本、来源、上游认证方式、原始制品与摘要、许可证、构建选项、平台、审核人和证据。若上游提供可验证签名，离线核验官方信任根及签名并记录证据；未提供或无法核验时明确标记，独立审核来源/构建后方可内部签名，内部签名不证明上游签名有效。未经审核或无证据不发布。

TUF targets 自定义元数据绑定唯一制品 ID、Core、精确版本、Linux、架构、构建选项、归档格式、来源 ID 与审核证据；标准 target 元数据绑定长度和 SHA-256。任务绑定同一制品 ID、版本及清单版本/摘要；节点与 Helper 独立验证授权和元数据，严格匹配本机平台及实际字节。源地址仅由 root 管控的固定 HTTPS 源映射确定，不接受任务 URL；限制重定向到已允许的 HTTPS 主机、解析后的网络地址、超时、大小和并发，禁止本地文件及非预期内网/元数据地址。

新安装或升级须验证完整 TUF 链、阈值、版本、有效期、目标长度/摘要及授权，时钟异常或 metadata 过期、无法刷新时失败关闭；已运行 LKG 不因离线自动停止。root 私有持久化记录各角色已见最高版本及事务状态，防止旧元数据回滚；恢复旧备份无法证明新鲜度时冻结写操作，凭可信当前状态及人工审核恢复，不得重置计数绕过防回滚。

限制归档压缩/展开大小、数量、深度和时间；拒绝绝对路径、`..`、所有链接、设备文件、特殊权限、重复目标及脚本/安装钩子。Helper 从安全文件描述符重新校验并在 root 拥有目录暂存，防止 TOCTOU；固定低权限隔离环境执行允许的预检。原子切换后健康检查，失败恢复 LKG，恢复失败明确告警并停止重试。

## 3. 轮换、撤销和降级

按 TUF root 顺序更新及旧根/新根各自阈值验证；替换 targets、snapshot、timestamp 密钥由有效 root 授权，审计并验证新链。泄露时暂停受影响发布、隔离密钥、撤销/替换并重新签发元数据；旧根阈值不可用时只允许本地人工通过独立可信渠道重新引导根，禁止远程静默重置信任。离线节点在信任可恢复前不得接受新安装。

Core 降级不是 TUF 元数据降级：须显式签名任务、独立高危审批，绑定节点、Core、精确版本、制品摘要、有效期和一次性授权；旧制品仍须出现在当前未过期 targets 且未撤销。事务内恢复已记录 LKG 不等于开放任意历史版本；仅在原事务授权范围内恢复并记录。Agent/Helper 更新须独立发布角色与高权限任务、监督健康确认和本地恢复；未完成演练前禁用远程更新。

## 4. 可测试验收（均待执行）

| 场景 | 预期 |
|---|---|
| 修改 targets 或不足阈值签名 | 拒绝，无安装副作用 |
| 过期 timestamp、旧 snapshot、时钟回拨或旧备份 | 拒绝新安装并告警，运行中 LKG 保持 |
| 替换目标字节、大小、架构或任务绑定 | Agent 和 Helper 任一不匹配即拒绝 |
| 未批准来源跳转、归档穿越/链接/炸弹 | 中止且不写目标目录 |
| 未授权降级、已撤销目标、根轮换缺旧/新阈值 | 拒绝 |
| 写满磁盘/断电/健康检查失败 | 对账恢复 LKG；无法恢复时明确失败 |

设计基线已冻结：TUF；离线 root 与 targets 角色阈值为 2-of-3；snapshot/timestamp 各使用分离的单用途在线密钥；Core 与 Agent/Helper targets 分离委派；过期/时钟异常时拒绝新安装，运行中 LKG 保持；降级要求目标仍受当前元数据信任并另有一次性独立审批。组织仍须任命实际密钥持有人和恢复责任人。具体 TUF 实现版本、密钥指纹、源映射、签名记录、互操作测试及独立安全批准 **待确定/待验证**；本文件不代表任何制品已可信，也不构成阶段 0 签核。
