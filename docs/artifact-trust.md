# 制品信任方案

阶段 3 的生产方案为 GitHub Releases 加单签名制品清单，由一位发布维护者运作。现有 Xray 本地和远程安装仍使用 TUF，单签名验证及迁移待实现。[发布手册](./phase-3-release.md) · [已实现与待办](./phase-3-progress.md)

## 1. 信任和发布

发布维护者离线保管一把 Ed25519 私钥。节点通过可信安装包或本地管理预置公钥并核对指纹。新清单使用已配置的公钥验证原始 JSON 字节的分离签名，然后解析内容。任务签发、配置签名和制品发布各使用对应的密钥。

清单必含格式版本、单调递增的 `manifest_version`、`expires_at` 及制品条目。条目绑定唯一制品 ID、组件、精确版本、OS、架构、文件名、来源 ID、归档格式、构建来源、长度、SHA-256 和核验记录。按严格的字段和资产映射解析，拒绝歧义和重复条目。核验记录保留上游签名状态。上游签名存在时验证签名，确实未发布签名时记录该事实。

Master 的只读目录从 `XTLS/Xray-core`、`SagerNet/sing-box`、`enfein/mieru` 获取版本发现信息。缓存同步按 GitHub API 的摘要和长度暂存官方最新版资产。安装授权以已验签的制品清单为准。

## 2. 取件、执行和恢复

- 远程任务绑定精确制品和清单版本，同时校验节点、操作、序号、有效期与租约。Agent 与 Helper 各自校验任务、公钥、清单版本、本机架构与制品字节，本地工具也使用同一清单校验逻辑。
- 按固定来源映射构造官方 GitHub Release URL。来源、文件名、架构、版本、长度和 SHA-256 全部匹配时，主控缓存可作为备用取件来源。下载仍限制重定向、网络地址、大小和超时，拒绝由任务提供的任意 URL。
- 取件和激活前检查当前清单及有效期。节点保存已接受的最高清单版本和该版清单摘要，拒绝回退或在同版本替换内容。清单无法刷新、过期或时钟异常时，拒绝新安装和版本变更。已提交实例可继续运行并由本地恢复流程恢复。旧备份无法证明清单状态新鲜时暂停制品变更，核对可信当前清单后恢复。
- Helper 从安全打开的文件描述符复验长度和摘要。解包限制大小、数量、深度和时间，拒绝异常路径、链接、设备文件和安装钩子。候选版本在固定低权限环境预检，原子切换后确认健康，失败恢复最后一次成功提交的版本和运行状态。

## 3. 撤销、轮换和显式降级

撤销制品时从下一版清单移除条目并发布。需要主动降级时使用显式任务，目标旧制品仍须列在当前有效清单中。事务自身的失败恢复按本地已提交状态执行。

发布密钥轮换通过可信带外渠道为节点更换本地公钥，清单版本继续递增。发布私钥遗失或泄露时暂停发布和新变更，人工重新分发信任并核对节点状态。该方案由一把发布密钥授权制品，公钥更换由节点管理方执行。

Agent/Helper 更新另行核验更新任务和成对制品。启动监督验证新版本后提交。若在切换中强制终止更新进程，下次启动恢复已提交的版本、节点身份和兼容状态。

## 4. 实现与验证

现有 `go-tuf/v2 v2.4.2` 客户端和 `mcui-tuf` 用于当前开发验证。当前 TUF 路径已经覆盖根轮换、阈值签名、目标撤销、固定源下载和本地 Xray 运行。迁移期间的配置与历史试验步骤见[旧版 TUF 手册](./phase-3-release.md#4-迁移前的-tuf-调试手册)。

单签名方案需要验证签名缺失或篡改、过期、清单回退和同版本内容变更。还需验证制品或架构不匹配、撤销、来源限制、直连与缓存取件一致，以及进程中断后的启动恢复。[阶段 3 验收范围](./phased-development-workflow.md#阶段-3xray-安全生命周期与自身更新)
