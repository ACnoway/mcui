# 威胁模型（阶段 0）

> 状态：设计与验收提案，待安全负责人及项目负责人人工评审；下列是要求和预期结果，不表示整体风险控制已经实现、实测或审计。阶段 0/1 的实现边界见[实施状态](./phase-0-1-implementation.md)。阶段范围以[分阶段流程](./phased-development-workflow.md)为准，权限规则见[panel-authz.md](./panel-authz.md)。

## 1. 资产、攻击者、边界

资产包括管理员身份/MFA 与会话、用户和订阅凭据、一次性安装码和节点 Token、签发与发布根密钥、审批与审计、任务序号和防重放账本、受信清单/制品、Core 配置和 LKG、用户流量计数、服务可用性与备份。假设外网攻击者可发请求、重放或篡改流量、提交恶意浏览器内容/制品；被盗的普通管理员拥有其合法范围内权限；恶意节点/Agent 可任意伪造其自身上报与 Helper 请求；受攻陷 Core 可执行其进程身份允许的动作；镜像或网络可能不可信。TLS、签名、操作系统和密码算法的正确实现是待验证前提，不是事实保证。

边界：浏览器↔Master，Web↔独立签发者，Master↔Agent，Agent↔Helper，Helper↔文件/systemd，Agent↔各 Core，发布根↔制品仓库，节点/Core↔客户端。节点本机 root、宿主内核、物理访问被攻陷不在隔离保证内；不承诺抵御已受控主控和所有签名根联合失陷，也不承诺对数据面流量内容或第三方上游软件的安全负责。

## 2. 失陷影响与残余风险

| 失陷主体 | 可能影响 | 预期限制及残余风险 |
|---|---|---|
| 普通管理员/其会话 | 读取或请求其已授权范围内数据、发起允许的任务 | 服务端范围限制、MFA/复验、独立审批；合法可见数据仍可泄露，审批者串通无法由该机制阻止 |
| Master Web/API 或数据库 | 读取其可访问数据，伪造请求、删改本地审计/状态、破坏可用性 | 独立签发者重新核验可信授权及审批，根私钥离线，独立审计备份；若攻击者能篡改签发者所依赖的全部身份/审批事实，不能声称签发隔离能阻止伪造 |
| 任务签发者/签名密钥 | 可签署其密钥授权范围的恶意任务 | Helper 约束、受信制品与配置策略限制，不等于能阻止合法类型的破坏性操作；须撤销密钥并恢复信任 |
| 安装码或节点 Token 泄露 | 持有者可以兑换未使用的安装码，或用 Token 冒充该节点、读取其配置并伪造上报 | 凭据限本节点，安装码短期且一次性。禁用可立即撤销凭据。Helper 独立验签、检查精确参数绑定及本机权限 |
| 单个 Core | 泄露自身配置与业务流量，滥用其获准资源 | 独立 UID、目录、socket 和沙箱；仍可能利用内核漏洞或误配横向移动 |
| Helper/root、发布根或主控高权限链联合失陷 | 节点特权操作或大范围供应链失陷 | 本设计不保证隔离；需本地隔离、撤销信任、独立介质重建与人工复核 |

## 3. 可执行的安全验收要求

| ID | 威胁/测试输入 | 预期结果及证据 |
|---|---|---|
| TM-01 | 缺少 Token、旧 Token、节点已禁用或节点 A 的 Token 请求 B 的任务 | 拒绝且无任务内容；审计含目标与拒绝原因，不含凭据 |
| TM-02 | 伪造 Master 身份，兑换已过期的安装码，或并发兑换同一安装码 | Agent 拒绝不可信主控；过期码被拒绝；同一安装码至多兑换一次 |
| TM-03 | 用户改 URL、批量 ID、导出或任务 ID 越过作用域 | 所有对象在服务端拒绝，列表/统计不泄露越权对象 |
| TM-04 | 越权管理员、自批、伪造/失效/复用审批，或审批后改目标/参数 | 签发失败；无有效签名及特权副作用，记录关联审计 |
| TM-05 | 篡改已签名任务、跨节点重放、序号缺口、过期/取消与重试竞态 | 拒绝或按冻结协议对账；不跳过缺口、不重复副作用；Agent 与 Helper 重启后结果确定 |
| TM-06 | 以 Agent 或其他本地用户请求任意路径、unit、URL，或替换签名字段 | Helper 拒绝；比较文件、服务状态和 root 账本证明无越权副作用 |
| TM-07 | 清单过期/回退、篡改包、错误架构、恶意归档链接/穿越/设备文件、资源耗尽 | 不安装或激活；旧 LKG 保持可用，记录脱敏错误 |
| TM-08 | 已签名配置包含公网管理 API、越界文件、未知字段或未批准外部资源 | 主控或 Agent 拒绝，目标及其他 Core 的 LKG 不变 |
| TM-09 | 浏览器 CSRF、跨域、节点上报 XSS、已撤销会话 | 请求被拒或输出安全编码；不泄露会话、订阅令牌、配置密钥 |
| TM-10 | 断电/磁盘满/健康检查失败、Agent/Helper 重启或旧备份恢复 | 依持久化事务恢复或显式停机并告警；无法证明防回退新鲜时暂停签发 |
| TM-11 | Core A 尝试读取 Agent Token、Helper socket 或 Core B 凭据 | OS 拒绝；记录身份、目标及结果，验证真实权限而非仅检查配置文本 |
| TM-12 | 重复流量批次、离线队列丢失或统计能力未知 | 不重复计量；缺口可见，未知标 `UNSUPPORTED` 且禁用精确额度 |

## 4. 审批和未闭合风险

项目负责人和安全负责人须批准攻击者模型、残余风险、签名密钥持有人和应急信任恢复；运维负责人须批准隔离与故障演练方案。测试证据须记录版本、平台、步骤、结果及责任人；无法复现或未执行均不得标记通过。平台测试基线、TUF 设计和签名协议语义已在配套文档中冻结为候选方案，但无双架构实测或安全签核。跨 Core 沙箱及 mita 内部状态恢复待未来阶段验证；审计独立备份、日志脱敏和密钥失陷演练同样需实施验证，不能将本威胁模型当作防护已生效。
