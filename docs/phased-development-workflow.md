> 版本：V1.0（实施草案）  
> 配套文档：[项目大纲与开发流程](./project-overview-and-development-workflow.md)、[Agent 技术设计文档](./agent-technical-design-v1.0.md)  
> 适用范围：Linux + systemd、amd64/arm64；Master + Web UI + Agent + Helper，按需安装 Xray、sing-box、mita。
> 平台验证：Debian 13.7 amd64 执行运行与故障测试，可在 `ro` 上用隔离环境完成；Linux arm64 验证构建。

## 1. 阶段原则和发布口径

1. **按实际依赖推进。** 每批交付一个可操作、可验证的能力。依赖的功能在隔离环境跑通后，就可以开始下游开发。生产部署、跨阶段的签核和完整 V1 验收在发布前集中完成。
2. **开发检查按改动选取。** 文档改动检查差异和链接。功能改动先做本地可执行的静态检查，推送后用 `ssh ro` 在 `/root/mcui` 的隔离检出验证同一提交。涉及协议、构建或部署的改动运行 `scripts/check-static.sh`，重点故障在对应功能完成时演练。每批记录提交和实际结果。
3. **先纵向闭环，后横向扩展。** Xray 先完成安全安装、配置、用户、流量可用性验证和回滚；再以相同门槛接入 sing-box、mita。每个 Core 只承诺经锁定版本验证的能力。
4. **失败必须可见。** `UNSUPPORTED`、统计不完整、配置待对账、回滚失败均为明确状态；不能显示成“零用量”“已成功”或“正常”。
5. **远程操作没有通用命令入口。** 只有签名结构化任务、受限配置和 Helper 固定操作。开发调试便利不能进入产品协议。

### 完整 V1 的范围

| 范围 | V1 交付要求 |
|---|---|
| 主控部署 | GitHub Releases 发布二进制包，一键脚本与 Compose 安装，默认仅本地访问，支持 HTTPS 反代和直连 TLS |
| 管理面 | 自动初始化一个管理员，支持 MFA、对象级授权、会话防护、敏感操作确认和审计。由同一账号管理节点、Core、配置、用户和订阅 |
| 节点 | 主控生成一条安装命令，自动安装空 Agent 和 Helper，配置可信材料并注册。支持 Token 轮换与撤销、心跳和受控恢复 |
| 任务与系统权限 | 签名任务、防重放、持久化状态、Helper 独立授权、可审计的失败恢复 |
| Core 生命周期 | 在面板选版本，默认最新可安装稳定版。程序校验官方包，管理员可安装、启停、升级、降级和卸载 Xray、sing-box、mita，每种 Core 单节点一个实例 |
| 配置与业务 | 逐 Core 能力矩阵、签名配置、语义策略、入站/用户、可用的统计、订阅与撤销 |
| 更新与资源 | Agent/Helper 独立签名、健康确认、自动回滚及本地恢复。发布前检查相关依赖漏洞，验证 SQLite 高频路径和低配主控的并发负载 |

用户级统计若在某锁定 Core 版本上不可靠，允许该项标记 `UNSUPPORTED`，但必须禁用该 Core 的精确额度控制，并在面板与文档中明示。跨节点额度属于近实时，不承诺严格瞬时一致。

## 阶段 5：安装方式与 Docker 构建

主控打包、可信接入和数据库优化可与阶段 3、4 并行开始。最终部署验收使用能实际连接的 Xray 场景。现有阶段 1 部署手册用于复现手工接入和迁移流程。

单管理员 Master 的 systemd 安装程序和 Compose 构建入口已写入[主控部署手册](./master-deployment.md)。首次换密、MFA、直连 TLS 和可信 HTTPS 反代已接入。以下勾选项记录各项验收是否完成。

- [ ] 在 GitHub Releases 发布主控和 Agent 安装包。验证一键脚本和 Compose 安装、版本化镜像、持久化配置与数据库、安装包信任和非特权容器运行。
- [ ] 默认仅本机可访问。验证用户自行配置的 HTTPS 反代和主控直连 TLS，包括外部地址、可信代理、Cookie 和 Agent 接入。
- [ ] 首次自动生成一个管理员，脚本和容器分各自入口输出一次初始凭据。验证首次换密与 MFA、异常中断、升级和已有数据卷复用。
- [ ] 面板命令已接入任务公钥、key ID、可选私有 CA 的自动配置，并保留已有信任与账本。完成干净 Linux/systemd 节点的安装、注册和上线验收，以及失败重试和令牌轮换演练。[Agent 安装](./phase-1-operations.md#节点首次接入)
- [ ] 节点 Token 摘要索引和心跳定向更新已接入。继续优化会话、审计和任务锁。记录低配单机并发心跳、管理操作、任务投递和数据库读写结果，验证撤销与故障恢复语义。

**退出门槛。** 两种主控部署入口均能在干净环境复现。节点上线后能由同一管理员选版本并开通可用的 Xray。凭据、网络及持久化边界有验证结果，并提供补丁升级和回退入口。

## 阶段 6：sing-box 与 mita 接入

**依赖**：Xray 最小演示及阶段 5 安装/构建路径。复用经过验证的 CoreManager、任务、配置和业务框架，不复制提权安装器。

- [ ] 分别核验锁定制品、配置语义、健康检查和生命周期，验证失败恢复与隔离；mita 须验证实际内部持久化与恢复。
- [ ] 逐 Core 完成入站、用户、配置对账、实际连接及订阅适配；逐版本验证统计、上报和额度，不可靠或未验证时标记 `UNSUPPORTED` 并禁用精确额度。
- [ ] 验证三种 Core 同节点共存、端口和文件访问隔离，一个 Core 更新不影响其他 Core；更新安装说明和能力矩阵。

**退出门槛**：逐 Core 的受控生命周期及业务能力有实测证据，已支持和不支持项清晰，共存及恢复通过验证。

## 阶段 7：发布安全验收与运行手册

**依赖**：阶段 0—6 的完整 V1 范围；项目内检查高风险模块并记录结果。

任务：

- [ ] API 操作/对象级权限、MFA、会话、CSRF、XSS、订阅令牌泄露与限流测试。
- [ ] 节点伪造/撤销、任务篡改/重放/取消/序号缺口、Helper 参数替换与路径逃逸测试。
- [ ] 恶意制品、过期清单、配置越权、候选二进制、Core 逃逸与跨 Core 文件读取测试。
- [ ] 主控离线 24 小时、数据库恢复、节点断网、Agent/Helper 更新断电、Core 回滚失败及本地人工恢复演练。
- [ ] fuzz、race、SBOM、签名发布及项目内安全检查。Go、前端、镜像与支持的 Core 的漏洞检查从首批发布物开始纳入，处理阻断问题并验证补丁交付。
- [ ] 写出安装、最小权限、备份、密钥轮换、恢复、撤销、漏洞报告和升级手册。

**发布阻断条件**：身份或授权绕过；任务/Helper 任意命令、路径或 Unit 操作；制品/配置未经可信校验即可激活；自身更新无可靠恢复；敏感凭据可通过普通 API/日志泄露；不可解释的流量误计；未解决 P0 安全缺陷。

**退出门槛**：项目大纲第 12 章与 Agent 文档第 14 章全部通过，三种 Core 的锁定版本能力及限制公开可见；发布产物可追溯并可从干净 VM 完整安装、更新和恢复。

## 3. 每阶段通用完成定义

每项功能合并前至少附带：协议或接口变更、权限与失败路径说明、相关安全测试、日志脱敏检查、版本兼容说明、回滚或人工恢复步骤。阶段负责人保存验收记录和未解决风险；跨阶段遗留的安全门槛必须回到设计评审，不能靠 UI 隐藏或操作手册绕过。

## 4. 当前开发顺序

1. **主控能安装、节点能上线。** 基于现有身份与任务底座做 GitHub 发布包、脚本和 Compose、首次登录、HTTPS 接入和 Agent 一键安装，同时优化心跳与节点鉴权。
2. **面板能直接管理 Xray。** 用单管理员、可信版本列表和后台签发串起安装与启停升级，交付受控入站并验证真实客户端连接及回滚。
3. **低配机器能持续运行和更新。** 完成数据库并发优化，验证补丁交付、安装重试、备份恢复、Agent/Helper 成对更新和故障回滚。
4. **扩展完整 V1。** 补齐统计、额度和订阅，接入 sing-box 与 mita，按阶段 7 验收全部支持能力。
