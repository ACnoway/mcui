# 轻量化多 Core 主控面板——分阶段开发流程

> 版本：V1.0（实施草案）  
> 配套文档：[项目大纲与开发流程](./project-overview-and-development-workflow.md)、[Agent 技术设计文档](./agent-technical-design-v1.0.md)  
> 适用范围：Linux + systemd、amd64/arm64；Master + Web UI + Agent + Helper，按需安装 Xray、sing-box、mita。

> 当前代码与验证证据见[阶段 0/1 实施状态](./phase-0-1-implementation.md)。阶段 0、1 尚未正式退出；本文件中的阶段 2 及后续任务仍是计划，当前不得据此提前启用。

## 1. 阶段原则和发布口径

1. **阶段按依赖推进。** 每个阶段先完成安全边界、失败恢复与验收，再接入下一项能力。内部演示不能代替发布验收。
2. **P0 与 P1 都属于完整 V1。** P0 是先行且不可跳过的安全门槛；P1 是 V1 发布前必须实现的业务闭环。只完成 P0 可标记为“内部安全底座”，不能标记为 V1。
3. **先纵向闭环，后横向扩展。** Xray 先完成安全安装、配置、用户、流量可用性验证和回滚；再以相同门槛接入 sing-box、mita。每个 Core 只承诺经锁定版本验证的能力。
4. **失败必须可见。** `UNSUPPORTED`、统计不完整、配置待对账、回滚失败均为明确状态；不能显示成“零用量”“已成功”或“正常”。
5. **远程操作没有通用命令入口。** 只有签名结构化任务、受限配置和 Helper 固定操作。开发调试便利不能进入产品协议。

### 完整 V1 的范围

| 范围 | V1 交付要求 |
|---|---|
| 管理面 | 管理员 MFA、服务端对象级授权、会话防护、审批与审计；节点、Core、配置、用户、任务与订阅管理 |
| 节点 | 空 Agent 注册、mTLS、轮换/撤销、心跳、离线续运行、受控恢复 |
| 任务与系统权限 | 签名任务、防重放、持久化状态、Helper 独立授权、可审计的失败恢复 |
| Core 生命周期 | Xray、sing-box、mita 按需安装、启停、升级/降级、卸载、回滚；每种 Core 单节点一个受控实例 |
| 配置与业务 | 逐 Core 能力矩阵、签名配置、语义策略、入站/用户、可用的统计、订阅与撤销 |
| 自身更新 | Agent/Helper 独立发布授权、健康确认、自动回滚及本地人工恢复 |

用户级统计若在某锁定 Core 版本上不可靠，允许该项标记 `UNSUPPORTED`，但必须禁用该 Core 的精确额度控制，并在面板与文档中明示。跨节点额度属于近实时，不承诺严格瞬时一致。

## 2. 阶段总览

| 阶段 | 目标 | 主要交付 | 退出门槛 |
|---|---|---|---|
| 0 | 冻结安全协议和范围 | 威胁模型、权限矩阵、协议、制品信任链、支持矩阵 | 关键安全决议无空白 |
| 1 | 面板与空 Agent 可信上线 | MFA、只读节点页、注册、mTLS、撤销 | 未授权主体无法读取节点任务或管理数据 |
| 2 | 签名任务与最小 Helper | 任务引擎、只读 Helper 操作、独立防重放 | 篡改/重放/越权请求均无特权副作用 |
| 3 | Xray 受控生命周期 | 可信安装、启停、更新、回滚、自身更新基础 | 故障不破坏 LKG，更新可恢复 |
| 4 | sing-box 与 mita 接入 | 逐版本适配及差异化状态 | 三种 Core 共存、相互隔离 |
| 5 | 配置与用户闭环 | 签名配置、语义策略、入站/用户、对账 | 恶意但已签名配置被拒，失败恢复 |
| 6 | 流量、额度和订阅 | 可靠上报、能力提示、令牌撤销 | 不重复计量、不泄露订阅令牌 |
| 7 | 发布安全验收 | 故障演练、审计、文档、发布门禁 | 全部 V1 条件通过，无未解决 P0 缺陷 |

## 阶段 0：设计冻结与项目基线

**输入**：两份设计草案。**先完成**：逐项决定尚待明确的问题，并形成可测试的协议，不以实现习惯代替设计决议。

任务：

- [ ] 固定 Linux/systemd 和 amd64/arm64 支持版本；为三种 Core 锁定首批测试版本、制品来源及构建选项。
- [x] 建立资产、攻击者能力和信任边界威胁模型草案；待独立安全评审并确认失陷影响与风险责任人。
- [x] 建立角色、操作与节点范围授权矩阵草案；管理员对象/委派范围、独立审批和首次引导仍待人工决议。
- [x] 形成节点证书注册、轮换、撤销及失效恢复协议草案；Master 根轮换、密钥托管与灾备仍未冻结。
- [x] 冻结 V1 task/config/cancel/skip 的结构、JCS/Ed25519 域分离和共享向量；序号缺口、取消/skip 竞争、租约及本地恢复尚未冻结。
- [ ] 批准并实现发布清单方案、根信任/密钥保管、离线过期、降级授权和恢复流程。
- [ ] 明确 Helper 固定操作/步骤参数绑定及逐 Core/版本配置允许字段。
- [ ] 配置 CI、分支保护、独立代码评审、完整工具链固定和依赖/发布门禁；当前仅有锁文件与静态检查脚本。

**交付物**：`architecture.md`、`threat-model.md`、`agent-protocol.md`、`panel-authz.md`、`config-policy.md`、`artifact-trust.md`、`core-compatibility.md`。

**退出门槛**：没有任意 Shell/URL/路径/Unit 操作；权限、审批、签名与密钥持有人明确；任务和配置签名有跨实现测试向量；所有后续阶段使用同一 V1 能力矩阵。

## 阶段 1：面板骨架与空 Agent 身份

**依赖**：阶段 0 身份和权限协议。此阶段仅展示节点状态与安全事件，不开放有副作用的节点操作。

任务：

- [x] SQLite 版本化实体表迁移及旧状态导入；TOTP、服务端会话撤销、15 分钟空闲/8 小时绝对超时、敏感操作 10 分钟 MFA 复验和进程内限流已实现。
- [x] 面板只读节点列表/详情和审计查询，并按角色与节点/组范围过滤；集成测试覆盖对象范围。管理员范围分配 UI 仍缺，当前 bootstrap 账号为全局安全管理员。
- [x] 直接 TLS 1.3 模式、Secure/HttpOnly/SameSite Cookie、CSRF token、Origin/Fetch Metadata 校验、CSP 和无宽松 CORS 已实现；TLS 反向代理模式不支持。
- [x] Agent 本地 Ed25519 身份、预置信任 Master CA、一次性邀请与 CSR 注册已实现；暂无安装包或 systemd 服务单元。
- [x] mTLS 心跳、禁用/证书撤销、幂等轮换和断线退避已实现；平台级非 root 部署、私钥托管和证书灾备待实机验证。
- [ ] 进行独立日志脱敏复核并实施主控数据库备份/恢复最小演练。

**交付物**：空 Agent、只读节点页面、安装手册、证书轮换与丢失恢复手册。

**退出门槛**：实现级测试已覆盖注册、撤销、范围读取和会话防护；仍须在干净 Linux VM 验证无 Core 注册与安装、补齐范围受限管理员的正式开通路径、独立安全评审及备份恢复演练。当前没有任务 API，不能将“无效节点不能获取任务”宣称为任务通道验收通过；阶段 2 的投递测试仍未开始。Master 失联时没有 Phase 1 Core 服务可供续行验证。

## 阶段 2：签名任务与 Helper 最小闭环

**依赖**：阶段 1 身份通道。先实现只读测试操作，验收后再开启安装。

任务：

- [ ] 主控按节点持久化分配序号；创建任务前检查权限、审批状态、目标及参数摘要；签发服务与 Web 进程隔离。
- [ ] Agent 验签、检查目标/类型/时间/序号，落盘后才执行；定义 ACK、重复投递、取消、租约过期和断档恢复。
- [ ] Helper 使用受限 Unix Socket、对端凭据与独立验签；对真实请求参数逐字段比对签名授权，root 私有账本记录已消耗步骤。
- [ ] 只暴露固定只读状态查询；模拟 Agent 被攻破、伪造服务名、路径和制品 ID。
- [ ] 面板展示任务来源、审批人、签发结果、执行步骤、失败码及关联审计；审计记录不包含凭据。

**交付物**：可运行的签名任务端到端测试、Helper 授权测试向量、任务恢复状态图。

**退出门槛**：篡改、重放、改目标、伪造审批、重复步骤和其他本机用户调用均不能造成特权副作用；Agent/Helper 重启后对账结果确定，不盲目重复操作。

## 阶段 3：Xray 安全生命周期与自身更新

**依赖**：阶段 2 授权链。第一种 Core 建立可复用的安装事务和回滚框架。

任务：

- [ ] 可信制品清单、固定源下载、大小/超时/跳转限制、摘要与签名验证、安全解包。
- [ ] Helper 将验证后的制品安装到 root 拥有的不可变目录；固定 systemd 单元、低权限 Core 用户与资源限制。
- [ ] Xray 安装、启停、升级、显式降级、卸载；配置与二进制 LKG、启动健康确认、失败回滚。
- [ ] 候选二进制/配置检查以低权限隔离运行；不执行制品自带脚本或自定义安装钩子。
- [ ] Agent/Helper 自身更新建立独立发布授权、旧版本监督与自动回滚；提供本地人工修复。
- [ ] 面板高危操作复验与审批，按任务真实结果展示状态。

**交付物**：Xray 生命周期闭环、事务与恢复日志、Agent/Helper 更新及本地修复手册。

**退出门槛**：恶意归档、错误摘要、错误架构和未批准版本均被拒；下载中断、磁盘满、断电、启动失败均不破坏 LKG；自身更新无法启动时可恢复旧版本。

## 阶段 4：sing-box 与 mita 接入

**依赖**：阶段 3 通用 CoreManager，不能复制出三套各自提权的安装器。

任务：

- [ ] 为 sing-box、mita 的锁定版本建立签名清单、固定进程身份、配置目录、systemd 单元和端口冲突校验。
- [ ] 分别实现生命周期与健康探针；核对升级和配置版本兼容性。
- [ ] 对 mita 验证内部配置持久化、`replace`/重启/恢复语义；不能仅靠外部 JSON 文件指针宣称回滚。
- [ ] 在面板按 Core/版本显示已验证能力；未知统计或热更新功能明确禁用。

**交付物**：三种 Core 的锁定版本兼容矩阵、差异化适配器、实机恢复记录。

**退出门槛**：空 Agent 可分别安装三种 Core；同节点共存且端口与文件访问隔离；更新一个 Core 不影响其他 Core；mita 的真实内部状态可恢复或明确进入安全停机。

## 阶段 5：安全配置、入站与用户

**依赖**：每种 Core 的配置语义及恢复边界已实测。

任务：

- [ ] 主控管理不可变完整配置 revision；签名绑定节点、Core、版本、字节摘要和单调序号。
- [ ] 主控和 Agent 双重实施逐 Core/版本配置策略；限制监听、管理 API、路径、外部资源、日志与出站行为。
- [ ] 低权限候选配置预检、受控切换、LKG 回滚；启动对账及手动回滚生成新 revision。
- [ ] 用户、入站、授权关系和必要凭据的最小可见范围；不在日志、审计导出或错误响应中泄露密钥。
- [ ] 面板配置差异、影响节点、审批与失败原因可查看；API 仍逐对象鉴权。

**交付物**：配置安全策略测试集、各 Core 配置适配、用户/入站闭环。

**退出门槛**：已签名但越权的配置被拒；错误配置不使 LKG 长期失效；仅目标节点和目标 Core 变更；权限不足的管理员无法读取其他节点或用户的敏感配置。

## 阶段 6：流量、额度与订阅

**依赖**：锁定版本的真实统计能力、用户映射和配置已稳定。

任务：

- [ ] 逐 Core 定义计数方向、用户标识、重启/窗口重置、数据缺口语义；不可靠者标记 `UNSUPPORTED`。
- [ ] Agent 先持久化增量批次再发送；主控事务去重；断网缓存有限额与丢失告警。
- [ ] 近实时额度的同步延迟和离线超额策略写入产品说明；禁止对不可靠 Core 提供精确额度控制。
- [ ] 生成可撤销/轮换的高熵订阅令牌，服务端只存摘要，限制频率与缓存，清理访问日志中的令牌。
- [ ] 面板显示统计健康度、未上报时段、能力差异及订阅撤销状态。

**交付物**：统计口径与误差说明、流量去重测试、订阅安全测试。

**退出门槛**：重复批次不重复累计；断网补报不会丢失已入库数据；数据缺口可见；订阅撤销生效且令牌不进入普通日志。

## 阶段 7：发布安全验收与运行手册

**依赖**：阶段 0—6 的完整 V1 范围；由非原实现者复核高风险模块。

任务：

- [ ] API 操作/对象级权限、MFA、会话、CSRF、XSS、订阅令牌泄露与限流测试。
- [ ] 节点伪造/撤销、任务篡改/重放/取消/序号缺口、Helper 参数替换与路径逃逸测试。
- [ ] 恶意制品、过期清单、配置越权、候选二进制、Core 逃逸与跨 Core 文件读取测试。
- [ ] 主控离线 24 小时、数据库恢复、节点断网、Agent/Helper 更新断电、Core 回滚失败及本地人工恢复演练。
- [ ] fuzz、race、依赖扫描、SBOM、签名发布及独立安全代码审查；处理全部阻断问题。
- [ ] 写出安装、最小权限、备份、密钥轮换、恢复、撤销、漏洞报告和升级手册。

**发布阻断条件**：身份或授权绕过；任务/Helper 任意命令、路径或 Unit 操作；制品/配置未经可信校验即可激活；自身更新无可靠恢复；敏感凭据可通过普通 API/日志泄露；不可解释的流量误计；未解决 P0 安全缺陷。

**退出门槛**：项目大纲第 12 章与 Agent 文档第 14 章全部通过，三种 Core 的锁定版本能力及限制公开可见；发布产物可追溯并可从干净 VM 完整安装、更新和恢复。

## 3. 每阶段通用完成定义

每项功能合并前至少附带：协议或接口变更、权限与失败路径说明、相关安全测试、日志脱敏检查、版本兼容说明、回滚或人工恢复步骤。阶段负责人保存验收记录和未解决风险；跨阶段遗留的安全门槛必须回到设计评审，不能靠 UI 隐藏或操作手册绕过。

## 4. 建议的第一批开发任务顺序

1. 协议、威胁模型、面板权限矩阵、配置策略和发布信任链。
2. 管理员身份/会话与空 Agent 注册、mTLS、撤销。
3. 签名任务与只读 Helper 测试操作。
4. Xray 生命周期和 Agent/Helper 更新恢复。
5. sing-box、mita 生命周期与各自持久化验证。
6. 签名配置、用户/入站、流量与订阅。
7. 全量安全验收和发布门禁。

此顺序是依赖关系，不是并行开发的限制；界面和文档可以提前做，但不得提前开放未经对应阶段验收的高风险操作。
