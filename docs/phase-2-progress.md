# 阶段 2 进度与未完成项

**状态：未完成。** 本文按阶段 2 最小目标记录当前代码与证据；协议/组件实现不等于运行时闭环，也不等于阶段退出、安全评审或生产授权。阶段 2 的规范要求见[分阶段开发流程第 2 阶段](./phased-development-workflow.md#阶段-2签名任务与-helper-最小闭环)及[V2 协议草案](./phase-2-protocol-draft.md)。

## 已完成

- 已批准只读状态任务 V2 开发基线：仅 `core.status`，核心为 Xray、sing-box、mita；规定 V2 独立签名域、严格结构、字段绑定，以及 `not-applicable` / `observe` 的只读语义。
- `internal/protocol` 实现 V2 结构校验与签名验证；共享向量由 Go 和 Node.js 测试检查。
- 有窄范围签名、验签、任务存储、节点序号分配/投递租约/ACK、Agent 本地账本与验签接收处理器、Helper 本地授权与账本的开发组件。
- 阶段 2 开发组件的 Go 测试曾通过（`go test ./...`）；这只是组件测试证据，不证明有任务运行时链路。
- 已确定状态查询**不单独审批**。实际接口仍须服务端验证管理员身份、节点对象范围与 `core.status` 操作权限，并写审计；请求字段不得伪装成审批证明。
- 已建立本进度文档，集中记录原始问题、范围约束和当前验收缺口。

## 未完成

以下对应阶段流程的五项阶段 2 任务，目前均未通过完整验收：

1. **主控签发/授权：**没有运行时任务创建 API；序号分配等组件未接入管理端鉴权/审计；签发服务与 Web 进程未隔离；独立签名密钥托管未完成。
2. **Agent 投递/处理：**Agent 还没有任务 Pull/ACK API；处理器只验签和写账本，没有完成可靠执行闭环。取消、租约重试、过期和序号断档的真实端到端恢复行为未验证。
3. **Helper：**公开 Unix Socket 执行入口目前失败关闭；真实 peer credentials、socket 报文、逐字段请求参数授权与固定状态读取未接通运行时。
4. **只读安全验收：**尚无端到端调用 Xray/sing-box/mita 固定状态查询的可运行测试，也没有完整的 Agent 失陷、伪造 service/unit/path/artifact 参数攻击测试。
5. **面板与审计：**没有任务状态、来源、签发/执行结果、步骤与失败码的面板展示，也没有与任务运行时相连的审计链路。

## 阻断因素与安全边界

- Helper 明确因独立防回退检查点、可信时间与授权恢复协议尚未实现而关闭公开执行入口；本地 helper ledger 内的高水位不能抵御账本整体回滚。现有 `checkpoint`、`checkpointstore`、`checkpointjournal` 是孤立实验组件，不等同于已部署、独立可信且经过故障验证的检查点。
- Agent 收件验签时间与持久化提交之间缺少原子可信时钟保证。
- 本阶段确定的**只读查询不单独审批**应落实为主控逐请求的操作者、角色、节点范围和操作权限检查，并写审计。若后续引入高危操作，仍按既有独立审批规则另行设计。
- V2 草案、阶段 2 文档和 README 已同步这一口径；不要把当前组件测试描述成整体安全验收通过。
