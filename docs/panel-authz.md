# 面板授权、审批与签发（阶段 0 设计）

> 本文记录 V1 单管理员目标、当前授权实现和后续多用户方案。阶段 1 已实现范围受限的账号管理，阶段 2 接入只读状态任务，阶段 3 的 Xray 生命周期目前仍使用运维员和独立签发工具。[当前 Xray 流程](./phase-3-approval.md)

## V1 单管理员

- 主控首次安装初始化一个管理员。首次换密并绑定 MFA 后，在同一个面板账号管理节点、Core 及已实现的配置和业务功能。第 1–3 节的委派角色和多人审批属于现有阶段记录或后续多用户设计。
- 服务端对每次请求核验会话、操作、目标对象与当前状态。浏览器写操作实施 CSRF 和来源校验，敏感操作按策略复验 MFA。HTTPS 反代与直连 TLS 都须保持 Secure Cookie 和正确的外部来源校验。节点 Token 继续限定在自己的节点。
- 后台签发服务通过受限接口复核操作白名单、节点、参数绑定、时限和重放约束，再记录签发依据。任务密钥和发布密钥分离。Agent 与 Helper 独立验签，Helper 仅执行固定操作。
- 面板直接执行安装、启停和升级，为降级及卸载显示具体目标并要求明确确认。Agent/Helper 更新使用独立发布签名和节点授权，信任恢复使用受保护的本地流程。

## 1. 原则与角色

本节的角色和委派范围用于说明当前阶段实现及后续多用户计划。

服务端默认拒绝，并在每次请求中检查认证身份、角色、操作、对象范围和资源当前状态。前端隐藏按钮不构成授权。列表、搜索、计数和导出必须先按范围过滤，再分页或聚合。涉及多个对象的写操作应先完整授权所有对象，再统一执行。

角色：R 为只读审计员；O 为节点运维员；S 为安全管理员；I 为不可交互登录的独立签发服务身份。角色本身不自动授予全局对象范围。节点及其节点审计继承节点范围；用户、订阅、Core、配置和任务须在相应资源实现前分别定义范围。

Bootstrap 创建一个全局 S。S 可新建 R/O 账号，范围必须是发起者当前可读节点 ID 与可管理节点组的子集；不可从该接口创建或管理 S。S 可列出自己及授权范围包含在自身范围内的 R/O 账号，禁用后端会撤销目标的所有会话。创建时一次性生成并仅返回 TOTP seed；账号列表与审计不含密码 hash 或 seed。密码由 S 在创建时输入并通过带外可信渠道交付。管理员角色/范围更改、S 账号恢复和双人首信任仪式仍待实现/批准；不得把单个 bootstrap S 当作可恢复的高可用管理员模型。

## 2. 角色 × 操作 × 资源提案

`✓` 表示仅限授权范围内允许；`A` 表示可发起但须独立审批；`P` 表示可审批但不能发起；`—` 表示默认拒绝。

| 操作与范围 | R | O | S | I |
|---|:---:|:---:|:---:|:---:|
| 节点列表/详情、节点范围内审计读取 | ✓ | ✓ | ✓ | — |
| 用户、入站、流量和订阅元数据读取 | ✓ | ✓ | ✓ | — |
| 创建节点、生成/补发安装命令或禁用/撤销节点 | — | — | ✓ | — |
| Xray 生命周期（阶段 3 隔离开发） | — | ✓ | — | — |
| Core 启停和升级 | — | A | P | — |
| Core 降级和卸载 | — | A | P | — |
| 创建/应用/回滚配置 revision | — | A | P | — |
| 用户、入站、授权和订阅令牌变更 | — | A | P | — |
| 固定 `core.status` 只读查询（节点范围内） | — | ✓ | ✓ | — |
| Agent/Helper 更新或凭据恢复申请 | — | A | P | — |
| 管理员角色/范围变更、MFA 重置、强制撤销会话 | — | — | A/P | — |
| 信任根/任务签名密钥变更和紧急恢复 | — | — | A/P | — |
| 按批准范围签发高危任务 | — | — | — | ✓ |

**已实现的子集。** S/O/R 的节点读取按节点 ID 和节点组过滤。S 管理节点及 auditor/operator 账号时检查对应范围，禁用账号时撤销其会话。阶段 2 的状态查询、未开始任务取消和已过期任务 skip 由 S/O 按节点范围发起。阶段 3 已开放可选的远程 Xray 安装，由 O 按下述授权流程发起。

安全管理员创建节点时检查目标组，生成或补发安装命令时检查节点范围并进行敏感操作复验。安装码仅通过生成命令的响应展示，审计保留操作人与目标节点。

## 3. 审批与签发提案

下述多人审批规则属于后续角色委派设计。独立签发和精确参数绑定同时适用于 V1 单管理员流程。

每个 `A` 操作至少需要一位与发起人不同、且对全部目标对象有当前授权的 S 审批。发起人不得审批自己的请求。信任根或任务签名密钥变更需要两位不同审批人，且都不同于发起人。紧急恢复不能静默绕过该规则；人员不足时暂停，直至有单独批准的线下治理流程。

审批必须绑定不可变请求版本、发起人、操作、完整目标和范围、规范参数摘要、风险级别、审批人身份与 MFA 复验、创建/过期时间、状态和使用次数。参数、目标、角色、范围或审批状态改变均使审批失效。签发身份须重新核验当前授权和审批来源，然后原子消费审批并持久化签发意图，之后才可投递。`approval_id` 本身不是审批证明。签发服务不得只信任可由失陷 Web 进程任意篡改的审批数据。

MFA 复验窗口固定为 10 分钟，高危任务提案有效期最长 30 分钟，任务签名有效期最长 10 分钟。Xray 安装由同一 O 发起并投递。独立签发服务校验运维员签名和当前可信策略，并持久化消费请求。主控持久化序号预留、请求摘要、已核验的签发任务、投递和结果。启用了独立检查点的主控还会在返回结果前更新检查点。当前只读查询签名有效 5 分钟。[Xray 安装授权和签发](./phase-3-approval.md)

### 阶段 3 隔离开发

隔离节点上的远程 Xray 生命周期操作由同一位具备节点范围的 O 经 MFA 发起并投递，复用独立签发、任务验签和审计。升级和降级同时绑定当前版本与目标制品。降级与卸载各自显示目标并要求明确确认。生产部署按已批准的权限策略启用。Agent/Helper 更新使用单独授权。

## 4. 会话、CSRF 与审计

阶段 1 要求 TOTP MFA 登录。服务端会话可撤销，空闲 15 分钟或绝对 8 小时后失效；敏感操作要求最近 10 分钟内通过 MFA 复验，否则应用提示重新输入验证码。Cookie 为 HttpOnly、SameSite Strict，并在直连 TLS 时设置 Secure。浏览器状态变更请求须携带会话 CSRF token，并通过同源 `Origin` 或 `Sec-Fetch-Site` 检查。Master 设置 CSP 和其他安全响应头，不开放宽松 CORS。节点文本以 Vue 插值输出，凭据不写入浏览器持久存储。

登录/bootstrap、邀请、注册和证书轮换有进程内限流；多 Master 进程间不共享限流状态。审计记录操作者、动作、资源、结果和时间。`mcuidb` 提供 SQLite 快照、结构与完整性验证及不覆盖式恢复候选；备份加密、独立不可变检查点、保留期、日志脱敏检查和敏感导出控制仍未实现。

## 5. 验收与未决要求

- 现有 API 已覆盖范围外节点与范围账号委派/撤销；随着分页、导出和跨资源对象加入，继续补充服务端过滤样例。
- R/O 子集委派已实现；S 角色委派、MFA 恢复、账号找回和双人首信任仍须在独立治理流程获批后实现。
- 在实现任何 `A/P` 功能前，测试自批、并发重复审批、参数更改、权限撤销、过期与崩溃恢复，并验证任务签名密钥隔离。
- 项目内检查 MFA、会话撤销、CSRF、CSP、XSS 输出编码、限流、审计脱敏和恢复流程；当前测试仅覆盖阶段 1 子集。
- 验证单管理员的对象授权、敏感操作确认和首次账号恢复，记录备份和审计保留策略与签发信任来源。多用户委派和多人审批纳入其后续版本的独立验收。
