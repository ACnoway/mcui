# 面板授权、审批与签发（阶段 0）

> 状态：具体设计提案，须项目负责人和安全负责人人工审批；不是已实现或已测试的能力。阶段 1 仅有只读节点、安全事件及身份管理，不因本矩阵而提前开放节点副作用。范围见 [分阶段流程](./phased-development-workflow.md)，边界见 [architecture.md](./architecture.md)。

## 1. 原则与作用域

服务端每次请求默认拒绝，认证后按角色、操作、资源范围及资源当前状态共同判定；前端隐藏不构成授权。角色可组合但不豁免职责分离；任何账号不得批准自己创建的高危请求。授权范围是显式分配的节点集合及用户集合，节点组是展开节点集合的管理方式，不自动授予全部节点；资源关系变更即时生效。节点及其 Core、配置、任务、节点审计继承该节点范围；用户、令牌及流量归属用户范围；关联资源操作必须同时具有所有涉及节点和用户的范围，缺一个即拒绝。跨范围的列表、搜索、计数和导出先过滤再分页/聚合；批量写入采用全量预授权、任一对象失败则整体不执行。不存在对象或无权访问可统一返回 404，拒绝详情仅进入受限审计。

角色：R 只读审计员；O 节点运维员；S 安全管理员（分配授权、审批和安全配置，**不因角色自动获得所有数据范围**）；I 独立签发服务身份，非人类、不允许交互登录。首次 S 创建和范围初始化通过受控本地引导及两名受托人员人工复核，禁止隐式默认超级用户；具体引导程序与恢复流程待审定。服务账号不得代替人类审批；删除/撤销用户权限与会话时签发流程必须重新检查。

## 2. 角色 × 操作 × 对象矩阵

标记：✓ 授权范围内可执行；A 可创建请求但需第 3 节审批；P 可独立审批，不含创建权；— 默认拒绝。多角色按授予权限并集计算，审批自利限制始终适用。敏感值默认不可读，以下读取不包括密钥明文。

| 操作（资源范围） | R | O | S | I |
|---|:---:|:---:|:---:|:---:|
| 节点、Core 状态、脱敏配置与任务读取（节点） | ✓ | ✓ | ✓ | — |
| 用户、入站关系、流量、订阅元数据读取（全部关联节点及用户） | ✓ | ✓ | ✓ | — |
| 脱敏审计/安全事件查询和导出（事件关联全部对象） | ✓ | ✓ | ✓ | — |
| 创建注册邀请、节点禁用/证书撤销（节点或预分配节点组） | — | — | ✓ | — |
| Core 启动/停止/重启、安装/升级（目标节点及 Core） | — | A | P | — |
| Core 卸载/降级（目标节点及 Core） | — | A | P | — |
| 配置 revision 创建、应用及回滚（目标节点、Core 和所有关联用户） | — | A | P | — |
| 入站、用户、授权关系变更（所有关联节点及用户） | — | A | P | — |
| 订阅令牌创建、轮换、撤销（用户及全部关联节点） | — | A | P | — |
| Agent 凭据轮换申请、Agent/Helper 更新（目标节点） | — | A | P | — |
| 管理员角色/范围变更、MFA 重置、会话强制撤销（目标管理员及受影响范围） | — | — | A/P | — |
| 信任根/任务签名密钥变更、紧急恢复（全局及全部目标） | — | — | A/P | — |
| 签发经过核验的精确任务（签发者授权的节点/操作范围） | — | — | — | ✓ |

S 在 `A/P` 行可创建或审批但不能自批；权限分配及范围应可限制 S 的管理对象，不允许操作者借权限变更给自己提权。创建用户时须先授权其目标用户集合/命名空间；节点首次注册的组及后续归属变更须由有该组授权的 S 管理。审计若涉及无权限对象，只提供不含关联对象内容的安全汇总或拒绝，不因审计角色获得全局明文。明确未列出的操作（包括明文私钥读取、任意命令、任意文件/URL/unit）一律拒绝；一次性订阅令牌仅在创建/轮换成功时向获授权发起人展示一次，数据库仅存摘要，普通读取/日志/导出不返回。

## 3. 审批、复验与签发

本提案选择所有矩阵中 A 操作至少一位**不同于发起人**且具备对应对象范围的 S 审批；卸载、降级、Agent/Helper 更新和管理员授权变更同样要求独立审批。信任根或任务签名密钥变更要求两位互不相同且均不同于发起人的 S 审批；应急恢复不得绕过此规则，人员不足则暂停并走经线下治理批准的恢复流程，不设软件自动豁免。S 自己创建 A/P 请求需另一 S 审批。审批人和发起人在创建、审批和签发关键点需要近期 MFA 复验；建议有效窗口 10 分钟，审批最多有效 30 分钟且单次使用，均待人工确认。

审批记录绑定不可变请求版本、发起人、操作、全部目标和范围、规范化参数摘要、风险级别、审批人及其复验、创建/过期时间、状态和使用次数。任何参数、目标、角色、范围、审批状态变化或过期都使请求失效，须重新审批。签发者基于可信身份/审批来源重新检查发起人与审批者当前权限、独立性、摘要、时间与目标；`approval_id` 只是索引。以事务或等价机制原子消费审批并持久化任务/签发意图，崩溃恢复不得重复签发不同任务或重复消费；完成前不向 Agent 投递。任务签名覆盖完整规范字段，具体格式、重放和恢复以 `agent-protocol.md` 的冻结规范为准。签发过程不可仅依赖可被失陷 Web 进程任意篡改的审批事实；若身份/审批信任源隔离不可证明，暂停签发并标记架构阻断。

## 4. 会话、审计与紧急处理

管理员 MFA 必需；会话服务端可撤销，退出/撤权即失效；Cookie 使用 `Secure`、`HttpOnly`、受限作用域及 `SameSite`，后者不替代所有状态变更请求的 CSRF token 和来源校验。限制 CORS、CSP，节点输入输出编码，不在浏览器持久存储凭据；登录及敏感操作限流。空闲/绝对超时具体值待人工批准，未设定和验证前不得上线。订阅端点独立鉴权、限流、禁止缓存且不得将令牌写访问日志。

审计串联请求人、对象、权限依据、请求版本/摘要、复验、审批人、签发者、任务 ID、执行结果及拒绝原因；禁止明文密码、MFA、私钥、订阅令牌和完整敏感配置。审计事件应追加并向独立位置受限备份，保留期及防篡改方案须审批；服务异常时对高危写操作默认关闭。泄露时撤销会话/凭据与待签审批、停止受影响签发，安全人员调查并通过独立渠道保全审计；已经离线的节点不能被保证即时感知撤销。

## 5. 验收与未决事项

- 对每一矩阵单元建立允许、拒绝及范围外负例；覆盖直接 API、对象 ID 替换、批量、分页/计数/搜索/导出和关联资源；未授权不得读写或泄漏对象存在性。
- 并发重复审批/签发、自批、两次审批同一人、改参数、撤权、过期、崩溃恢复：均不得生成未经授权签名或重复特权副作用。
- 验证 MFA、敏感复验、会话立即撤销、CSRF/CORS/CSP、XSS、日志和订阅令牌脱敏；检查审计与任务结果关联。
- 人工审批：角色实际人员、范围委派与首次引导/灾备流程、超时数值、审批人数和窗口、审计保留期限及独立签发信任来源。当前节点/用户范围尚不能表达矩阵中的管理员对象、全局信任资源和节点组/命名空间授权；须定义其独立作用域、委派边界及变更后重新鉴权规则并补充正反例，否则相关操作默认拒绝。未审批或未验证前本文件不构成阶段退出证明。
