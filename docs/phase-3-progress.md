## 已实现的只读版本目录

- Master 为已登录管理员提供 `GET /api/v1/admin/cores/releases`，从三个固定 GitHub 官方仓库读取 Xray、sing-box 和 mita 的最近发布版本、发布页及制品链接。
- 上游请求使用固定 API 地址、8 秒超时、单请求响应大小上限和不跟随重定向的 HTTP 客户端。返回的发布页与制品链接必须匹配对应官方仓库、版本和文件名；不匹配的记录不进入面板。
- Master 进程内缓存目录 10 分钟；上游暂时不可用时，最多返回 24 小时内的最近成功快照并标记为过期。缓存不会跨 Master 重启保留。
- 面板展示版本、预发布标记、发布时间、官方发布页、制品文件名、大小和 GitHub Release API 提供的 SHA-256 digest（若有）。
- 此目录仅用于版本发现。digest 尚未经过本项目 TUF targets 阈值签署；当前没有主控备用制品、安装任务、Agent 下载路径、Helper 解包/安装事务或 Core 服务管理操作。

## 后续工作

1. 部署时从官方源取得每种 Core 一个固定版本的 amd64/arm64 备用制品；记录精确版本、源 URL、字节数、摘要和上游签名事实。缓存副本只对版本、架构和摘要全部匹配的请求可用。
2. 实现受信任制品元数据、固定官方源下载、请求/响应大小与时间限制、重定向主机限制、摘要/签名校验及安全解包。任务绑定制品 ID、精确版本、架构和摘要，不接受任意 URL。
3. 建立高危操作 MFA 复验和独立审批后，增加签名安装/升级/显式降级/卸载任务及 Helper 固定操作。
4. 为 Xray 增加不可变版本目录、固定 systemd unit、独立低权限账号、健康确认、LKG 恢复和启动对账。
5. 实现 Agent/Helper 独立授权更新、旧版本监督、自动恢复和本地人工修复；完成失败恢复演练前保持远程自身更新关闭。
6. 在 Debian 13.7 amd64/arm64 分别测试制品拒绝、下载中断、磁盘不足、错误架构、恶意归档、启动失败和恢复；按证据更新能力矩阵。
